# Testing Graph Memory in an Agent

With the graph store wired into mem0, a normal conversation builds a
knowledge graph underneath it - no manual Cypher, no schema design.

---

## 🟢 Beginner — what actually happens

```text
  "Hey, my name is Piyush. I like pizza and hot tea."
                      |
                      v
            mem0 (with graph store configured)
                      |
                      v
       (Piyush)--likes-->(Pizza)
       (Piyush)--likes-->(Hot Tea)
```

No manual Cypher was written. The LLM generated and ran it behind the
scenes - this is the live proof of the earlier point: you describe the
relationship in plain language, the graph builds itself.

---

## 🟡 Intermediate — two things worth internalizing

### 1. The dependency-error-fix loop

```text
Error: "cannot import memory graph ... LangChain Neo4j is not installed"
         |
         v
   pip install langchain-neo4j
         |
         v
   (hits a second missing package - same pattern)
         |
         v
   read the error, pip install what it names, re-run
```

A generalizable debugging habit, not Neo4j-specific: the error message
names exactly what's missing - install that, rerun, repeat until clean.

### 2. The graph grows as you talk - it doesn't just store one fact

| You said | New nodes/edges added |
|---|---|
| "My name is Piyush, I like pizza and hot tea" | `Piyush --likes--> Pizza`, `Piyush --likes--> Hot Tea` |
| "I'm a full-stack developer, tech stack is Node.js + JavaScript + Postgres" | `Piyush --works_with--> Node.js / JavaScript / Postgres` |
| "I also work with Python for GenAI workloads" | `Piyush --works_with--> Python --used_for--> Generative AI` |

Each new sentence **adds to** the existing graph around the same `Piyush`
node - it doesn't replace what was already there.

---

## 🔴 Expert — why this is the actual payoff

The real test: asking *"what is my tech stack?"* correctly combined
**Node.js, JavaScript, Postgres, and Python** - pulled together from four
separate, unrelated conversation turns.

That's what a flat vector store struggles with: it can find "a message
similar to tech stack," but stitching together facts scattered across an
entire conversation into one coherent answer is exactly what a **graph of
relationships** is built for - walk the edges out from the user node,
collect everything connected, done.

**Operational gotcha:** new facts don't appear in the graph instantly -
there's a small lag before a freshly-added relationship shows up on
query/refresh. Not a bug, just expected latency while the write settles.

| Term | One-line definition |
|---|---|
| **Graph memory in mem0** | conversation facts automatically become nodes + edges, no manual Cypher |
| **The dependency-error loop** | read the error, install what it names, rerun, repeat |
